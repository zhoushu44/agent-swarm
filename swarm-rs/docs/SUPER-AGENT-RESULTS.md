# 实验报告：《Super-agent 开放问题求解报告》三项机理仿真验证

> **性质声明（先读这个）**：本目录的三项实验是**机理级离散事件仿真**，不是端到端系统实验。
> 原文 §7 的实验运行了真实模型与真实消息流；本仿真**没有 LLM 在环**——凡依赖"模型智能"的量
> （决策质量曲线、协商成败率、检索语义）均以外生参数给定。仿真验证的是**调度、竞争与检索的
> 结构性机理**：这些机理不依赖模型聪明程度，因此可以用可控参数扫描得到干净的因果结论。
> 证据强度排序：原文端到端实验 > 本机理仿真 > 报告的纯思辨论证。仿真代码全部可复现
> （`python expN_*.py`，仅依赖 Python 标准库，5 seeds 取均值）。

## Exp1：Router 饱和信号的先导性（验证报告 §3.2 扩缩容决策表）

**模型**：take-all 批处理服务器，单轮服务时长 `t(b)=T0+C·b`，由原文 §7.2 压测的两个实测点
校准（batch=1.0→2.5s，batch=2.8→3.9s ⟹ T0=1.72s，C=0.778s/条）；质量模型：模型单轮可靠
决策容量 K=6 条，超出后错误率线性上升（+2%/条）；崩坏定义为可观测错误率 >10%。

**校准核对**：在原文压测的最大负载 40 条/min 处，本模型给出 batch=2.50（原文 2.8，偏差 11%）。
时延口径差异需说明：原文"单个决定分摊推理时间"=服务时间均摊（1.6s）；本仿真 p50=6.1s 是
**端到端"触发→决定"时延**（含批组装等待），是用户可感知口径，两者不矛盾。

**结果**（负载 λ 扫描 3→81 条/min，信号阈值见脚本头部）：

| 信号 | 首次触发负载 | 相对崩坏点(72条/min)的领先余量 |
|---|---|---|
| S3 p95时延>10s | 39 条/min | **+46%**（最早） |
| S4 重派发率>3% | 51 条/min | +29% |
| S2 批大小>0.8K | 54 条/min | +25% |
| S1 队列深度持续积压 | 78 条/min | **−8%（崩坏之后才触发！）** |

**发现**：

1. **修正报告 §3.2 的决策表排序**：在 take-all 批处理下，**队列深度是滞后指标**——批处理把
   积压"藏"在服务轮内部，队列只在 batch 顶到 B_MAX 上限后才外溢，此时错误率已经越线。
   正确的监控优先级应为：**p95 时延 → 重派发率/批大小 → （队列深度仅作饱和确认，不作预警）**。
2. p95 时延是最便宜且最早的先导信号（从低负载起平滑增长、无悬崖）；重派发率是"决策质量"
   的可观测代理（操作者看不到模型内部错误率，但看得到 Worker 交回任务的频率）。
3. 有趣的巧合：原文压测的最大档 40 条/min，恰好在 p95 时延突破 10s SLO 的位置附近——
   即原文自己的压测就停在了"该设监控"的负载量级。
4. 敏感性：S3 的领先余量依赖 SLO 选取（10s 为示例值）；S4/S2 的触发点只依赖 K 与错误率
   曲线假设，K 的真实值需要原文团队用回归集标定。

**复现**：`python exp1_router_saturation.py`（输出完整扫描表 + `exp1_result.json`）

## Exp2：Worker 共享资源写冲突的三种治理模式消融（验证报告 §3.4）

**设定**：4 Workers × 10 共享资源，单 Worker 利用率 0.7，8 小时地平线，5 seeds。
三种模式：naive（先干再说，撞车按 lost-update 语义退避重做 + Router 仲裁）、
lease（确定性租约注册表，忙则 FIFO 排队）、llm-negotiate（冲突后双方 LLM 协商 3 轮，
20% 竞态失败退化为踩踏）。

**结果**（均值）：

| 模式 | 完成任务 | 平均时延 | 返工次数 | 浪费工时 | Router仲裁消息 | 额外 token |
|---|---|---|---|---|---|---|
| naive | 553 | 136s | 97.6 | 167 min | 97.6 | 195,200 |
| **lease** | **603** | 116s | **0** | **0** | **0** | **0** |
| llm-negotiate | 580 | 118s | 21.4 | 51 min | 0 | **1,209,600** |

**发现**：

1. **租约锁不仅清零返工与 Router 仲裁负载，吞吐反而更高**（603 vs 553，+9%）——省下的
   返工工时大于排队等待成本（等待合计 2.06 工时 ≈ 4 Worker×8h 的 6.4%）。报告 §3.4 的
   "资源互斥交给确定性代码"在机理层面成立。
2. **LLM 协商是昂贵的反模式**：112 次冲突协商烧掉 121 万 token（摊到每任务约 2000 token），
   仍留下 21 次竞态返工——印证"不要让 LLM 高频当裁判"。
3. naive 模式的仲裁消息（98 条/8h）全部涌向 Router——这就是报告 §3.4 说的"Router 变成
   传声筒"坏味道的定量形态，对应"何时需要引入 Worker 间直接协调"的信号 ②。
4. 局限：冲突率由资源数/利用率参数决定（本设定约 18-25%）；租约的等待成本在利用率更高时
   会上升（租约队列变成瓶颈），届时应扩大资源粒度——这与报告"租约 TTL + 心跳续期"的
   设计联动。

**复现**：`python exp2_lease_ablation.py`

## Exp3：长程记忆——情景衰减 vs 记忆固化（验证报告 §3.5）

**设定**：60 天×30 事件/天、50 主题（随机活跃窗口，事件只落在窗口内）、事件 3 关键词
+15% 噪音；情景记忆按半衰期 hl 衰减（保留词数 = round(3·0.5^(age/hl))，可衰减至 0）；
固化卡片在事件**新鲜时**生成（关键词并集，不衰减）——对应"记忆压实 Worker 在闲时运行"。
检索带近因偏好（0.3·exp(−age/30)），模拟 Agent 检索的近因偏差。查询：第 60 天对冷主题
（最后事件早于第 25 天）发 20 条回忆查询。

**结果**（recall@10，5 seeds 均值）：

| 情景半衰期 | 朴素全量情景库 | 固化混合库(卡片+近期) |
|---|---|---|
| ∞（不衰减） | 100% | 100% |
| 56 天 | 100% | 100% |
| 28 天 | 60% | 100% |
| 21 天 | 67%* | 100% |
| 14 天 | 13% | 100% |
| 7 天 | **0%** | 100% |

*21 与 28 天的非单调差异在种子噪声范围内（±1 条查询 = ±5%）。

**发现**：

1. **固化机制的价值随情景衰减强度单调放大**：衰减温和（hl≥56 天）时朴素检索尚可，
   衰减到人类式遗忘水平（hl≈2-4 周）时朴素召回崩至 13-67%，固化卡片不受影响。
   这正是神经科学"系统巩固"（海马体细节衰退、皮层要点保留）的检索学后果，也是报告
   §3.5"记忆压实 Worker"存在的根本理由：**固化必须在遗忘之前发生**。
2. token 经济性：朴素库 400 tok/查询换 0-10 次命中；混合库约 620 tok/查询（1-2 张卡片
   + 近期事件做背景）**必中**。信息密度差距随语龄拉大。
3. 口径诚实说明：① 卡片=关键词并集是固化的理想上限，真实压实有损（本体漂移、压缩错误），
   实际曲线会介于两列之间；② 关键词衰减是语义衰减的粗暴代理，向量检索的语义泛化会让
   朴素库的悬崖变缓，但方向不变；③ 混合库的 top-10 噪音率高（90%）是口径问题——卡片排
   第一、其余槽位被近期事件填充（这本身是合理的上下文构成）；④ 本实验只测检索/注入层，
   L4 审计层的原始事件仍可经链式召回按需细读。
4. 与报告 §3.5 度量建议的对接：跨月任务恢复成功率 ≈ 本实验的 recall@10；"错误记忆率"
   对应卡片的压缩噪声（参数 15%），留待真实系统测。

**复现**：`python exp3_memory_consolidation.py`

## 共同局限与下一步

1. **无 LLM 在环**：决策质量、协商成败、语义检索全部外生给定。三项实验证明的是结构机理
   （排队论、租约语义、巩固-遗忘不对称），不证明任何模型能力主张。
2. **常数假设**：K_QUAL=6、RACE_P=0.2、近因权重 0.3 等需要真实系统标定；扫描表已给出
   对这些常数的敏感性方向。
3. **下一步（对应报告附录 B）**：#3 记忆压实消融与 #1 切分点验证可在接入真实 LLM 的
   dsh-superagent-prototype 上重跑（原型仓库开源、MIT）；#5/#6（通告器、接管协议）需要
   人类被试，无法仿真。
